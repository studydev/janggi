# 장기 (將棋 · Janggi)

웹으로 즐기는 한국 장기. **규칙 엔진과 UI가 완전히 분리**되어 있어, `src/engine/` 만으로
콘솔에서 대국을 끝까지 진행할 수 있습니다.

- 로컬 2인 대국 (한 화면에서 번갈아)
- 마·상 초기 배치 4종 선택
- 한 수 쉬기 · 무르기 · 기권 · 무승부 제안
- 외통 · 빅장 · 국면 반복 · 기물 점수제 판정
- 기보 표기 / JSON 내보내기·불러오기 / 리플레이 / 새로고침 복구
- 클릭 · 드래그 앤 드롭 · 키보드 조작, 색맹 대응 팔레트, PWA 오프라인 실행

---

## 실행 방법

```bash
npm install
```

개발 서버:

```bash
npm run dev
```

프로덕션 빌드와 미리보기:

```bash
npm run build && npm run preview
```

### 엔진만 쓰기 (UI 없이)

콘솔에서 랜덤 대국을 한 판 끝까지 돌립니다.

```bash
npm run play -- 7
```

perft 기준값 산출:

```bash
npm run perft -- 3
```

랜덤 대국 1000판 규칙 위반 검사:

```bash
npm run test:soak
```

### 테스트

```bash
npm test
```

`npm test` 에는 랜덤 대국 1000판 소크 테스트가 포함되어 있어 약 15~20초 걸립니다.
빠르게 돌리려면:

```bash
npx vitest run --exclude "**/soak.test.ts"
```

## 아키텍처

```
src/
  engine/            순수 TypeScript. React / DOM / 브라우저 API 참조 금지.
    types.ts         Side, PieceType, Position, GameState, 기물 점수
    board.ts         좌표 변환, 궁성 기하, 초기 배치, debugPrint
    moves/           기물별 의사이동(pseudo-legal) 생성기
      rays.ts        차·포가 공유하는 직진 경로 (궁성 대각선 포함)
      cha.ts po.ts ma.ts sang.ts gung.ts jol.ts
      index.ts       생성기 디스패처 + 공격 후보 사전 필터
    rules.ts         공격/장군 판정, 합법수 필터, makeMove / pass / undoMove
    result.ts        외통 · 빅장 · 국면 반복 · 점수 · 최종 판정
    record.ts        기보 직렬화 / 검증 / 리플레이
    janggi-notation.ts  표기 문자열을 만드는 유일한 장소
    perft.ts         합법수 트리 노드 수 (회귀 기준값)
    selfplay.ts      자기대국 + 불변식 검사기

  ui/                렌더링과 입력만. 규칙 판단 로직 없음.
    components/Board.tsx   SVG 보드 (props 만 그린다)
    components/…           설정 화면, 대국 화면, 기보, 사이드 패널, 다이얼로그
    state/gameReducer.ts   useReducer 상태. 액션은 엔진 함수만 호출한다.
    state/storage.ts       localStorage / 파일 입출력 (브라우저 API는 여기에만)
    boardGeometry.ts       보드 좌표 <-> SVG 좌표
    usePieceIds.ts         이동 트랜지션용 기물 식별자 추적

  scripts/           콘솔 도구 (랜덤 대국, perft, 소크)
```

### 지켜지는 경계

| 규칙 | 어떻게 강제되는가 |
|---|---|
| 엔진은 순수 함수 | `src/engine/` 어디에도 React/DOM import 가 없다. Vitest 는 node 환경에서 돈다. |
| UI 는 규칙을 모른다 | `Board.tsx` 는 `legalTargets` 를 props 로만 받는다. 합법 여부를 스스로 계산하지 않는다. |
| 상태는 불변 | `makeMove` 는 새 `GameState` 를 반환한다. 소크 테스트가 undo 일치를 매 수 검사한다. |
| 표기는 한 곳에서 | 좌표·기물 문자열은 `janggi-notation.ts` 밖에서 조립하지 않는다. |

## 규칙 출처

모든 규칙 판단의 근거는 저장소 루트의 **[RULES.md](RULES.md)** 입니다.
코드의 각 모듈 주석은 자신이 구현하는 RULES.md 항목을 인용합니다.
규칙이 애매하면 다른 체스류 게임의 상식으로 메우지 않고 RULES.md 를 고칩니다.

### 샹치(중국 장기)와 다른 점 — 구현에서 가장 자주 틀리는 부분

| 항목 | 장기 (이 구현) | 샹치 (이렇게 짜면 오답) |
|---|---|---|
| 강(河) | **없음** | 강이 있고 상은 못 건넘 |
| 상(象) | 1칸 직진 + 2칸 대각 (총 3칸) | 2칸 대각만 |
| 포(包) | **이동·공격 모두** 반드시 하나를 넘어야 함 | 이동은 차처럼, 공격만 넘음 |
| 포끼리 | 포를 넘을 수 없고 포를 잡을 수도 없음 | 제한 없음 |
| 졸/병 | 처음부터 옆으로 이동 가능 | 강 건너야 옆 이동 |
| 차·궁·사 | 궁성 안 대각선 이동 가능 | 대각선 없음 |
| 한 수 쉬기 | **허용** | 불가 |
| 초기 배치 | 마·상 위치를 대국 전에 선택 | 고정 |

`src/engine/__tests__/` 의 각 기물 테스트는 이 차이를 직접 고정합니다.
특히 `po.test.ts` 는 「포대 없이 이동 불가」, 「포를 넘기 불가」, 「포 잡기 불가」를 명시적으로 검사합니다.

## 검증

| 검사 | 내용 |
|---|---|
| 기물별 이동 테스트 | 7종 전부. 다리 막힘, 경로 차단, 궁성 이탈, 뒤로 이동 금지 등 |
| perft | 초기 국면 depth 1~3 노드 수를 배치 4종에 대해 고정 |
| 랜덤 대국 1000판 | 매 수마다 궁 잡힘 / 보드 이탈 / 궁성 이탈 / 포 규칙 / 졸 후진 / undo 불일치 검사 |
| 기보 왕복 | JSON 내보내기 → 불러오기 후 국면 일치 |
| 화면 상태 | 선택·착수·쉬기·무르기·리플레이·기권·합의 전이 |
| 보드 렌더 | 교차점 90개, 궁성 대각선 좌표, 강조 표시, aria-label |

perft 기준값 (양쪽 같은 배치):

| 배치 | depth 1 | depth 2 | depth 3 |
|---|---|---|---|
| 마상마상 (MSMS) | 31 | 961 | 30,506 |
| 상마상마 (SMSM) | 31 | 961 | 30,506 |
| 마상상마 (MSSM) | 31 | 961 | 30,353 |
| 상마마상 (SMMS) | 31 | 961 | 30,659 |

초기 국면의 31수는 손으로도 검산됩니다:
차 2+2, 마 2+1, 상 0+1, 사 2+2, 궁 6, **포 0+0**, 졸 2+3+3+3+2 = 31.
(포가 0인 이유: 세로로는 상대 포가, 가로로는 아군 포가 첫 기물이라 넘을 수 없습니다.)

perft 는 한 수 쉬기를 세지 않습니다. 모든 국면에서 항상 1을 더하는 상수라
기물 이동 규칙의 회귀를 잡는 데 도움이 되지 않기 때문입니다.

## 접근성

- 모든 교차점에 `aria-label` (예: "초(楚) 차, 10행 1열"). 표기 설정과 무관하게 한글로 읽습니다.
- 키보드만으로 조작: 보드에 포커스 → 방향키로 이동 → Enter 로 선택/착수.
  `aria-activedescendant` 로 현재 지점을 알립니다.
- 진영을 색으로만 구분하지 않습니다: 한(漢)은 팔각형, 초(楚)는 원형 (설정에서 끌 수 있음).
  기물 표기도 다릅니다 (漢/楚, 兵/卒).
- 색맹 대응 팔레트 (주황/파랑) 제공.
- `prefers-reduced-motion` 을 존중해 이동 애니메이션과 장군 깜빡임을 끕니다.
- 버튼·선택지의 최소 높이는 44px 입니다.

**터치 타깃에 관한 한계**: 9열 보드에서 교차점 간격이 곧 터치 타깃 크기입니다.
`8 × 44px = 352px` 에 기물 지름까지 더해야 하므로, 폭 400px 미만의 화면에서
44px 간격은 기하학적으로 불가능합니다. 그래서 좁은 화면에서는 주변 여백을 최대한 줄여
**가능한 최대 간격**을 확보합니다 (375px 뷰포트에서 약 39px, 가로 스크롤 없음).
판정 영역은 서로 겹치지 않는 한도까지 넓혀 두었습니다.

## 배포

- `vite build` 결과는 `dist/` 에 생성되며, `base: './'` 이므로 하위 경로 호스팅도 됩니다.
- React 는 별도 청크로 분리됩니다.
- PWA: `public/manifest.webmanifest` + `public/sw.js`.
  서비스 워커는 프로덕션 빌드에서만 등록되며, 앱 셸을 캐시해 **오프라인에서도 로컬 대국**이 됩니다.
  (규칙 엔진이 전부 클라이언트에서 도는 구조라 서버가 필요 없습니다.)
- 아이콘은 `node scripts/make-icons.mjs` 로 생성합니다 (의존성 없는 PNG 인코더).
- 렌더링이 깨져도 `ErrorBoundary` 가 복구 경로(새로고침 / 저장된 대국 삭제)를 제공합니다.
